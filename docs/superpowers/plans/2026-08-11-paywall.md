# План Б: деньги — заказы, касса, право доступа

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Продавать полный разбор за 199 ₽: бесплатно вердикт, за деньги — остальное, с полным рабочим циклом оплаты на поддельной кассе.

**Architecture:** Право смотреть платное живёт на сервере записью «аккаунт → steamId», а не в куке. Приёмщик оплаты спрятан за интерфейсом с двумя реализациями: заглушка (сегодня) и ЮКасса (потом); заглушка дёргает тот же вебхук, что настоящая касса, поэтому проверяется весь путь целиком. Платная часть карточки не уезжает в браузер вообще: сервер отдаёт урезанную карточку, где закрытые поля заменены пустышкой, а размытие — оформление поверх пустышки.

**Tech Stack:** Next 16 (App Router), TypeScript strict, better-sqlite3, vitest, next-intl (`ru` и `en`).

## Global Constraints

- Новых зависимостей не добавляем.
- Проверки: `npm run verify` (типы + линтер + тесты). Потолок линтера строгий — `--max-warnings 0`.
- Цена: **19900 копеек**, валюта `RUB`. Хранить в копейках, показывать рублями.
- Один переключатель `PAYWALL_MODE` на три значения: `off` (по умолчанию), `stub`, `live`. Никаких отдельных флагов: старые `DISABLE_GATE` и `NEXT_PUBLIC_DISABLE_GATE` удаляются.
- Секрет подписи вебхука — `PAYMENT_WEBHOOK_SECRET`. Нет секрета — приёмщик не стартует. Проверка пишется как «секрет обязателен», а НЕ как «если секрет задан»: в этом проекте вторая форма уже однажды открыла телеграм-вебхук всему миру.
- Ошибка любого рода закрывает доступ, а не открывает.
- Из route-файла Next экспортируются ТОЛЬКО обработчик и `runtime`.
- Тексты для посетителя — через next-intl, одинаковые ключи в `messages/ru.json` и `messages/en.json`.
- Комментарии в коде — по-русски, объясняют ПОЧЕМУ.
- Вёрстка держит телефон от 320px.

## Решения владельца (2026-08-11)

- **Вход просят только при покупке.** Кнопки «Войти» в шапке нет; сайт остаётся анонимным до нажатия «Открыть полный разбор».
- **Поддельная касса включается сразу для всех** после выката, с несмываемой плашкой «тестовый режим, деньги не списываются».
- Право доступа **бессрочное**: контент уже сгенерирован, отбирать нечего.
- Покупка **не требует** доказывать владение Steam-аккаунтом: купить можно любой разбор.

- [ ] **Шаг 3: Схема**

`lib/billing/db.ts` — своих соединений не заводит, берёт готовое:

```ts
import { getIdentityDb } from "../identity/db";

let migrated = false;

/**
 * Таблицы денег живут в том же файле базы, что и аккаунты: у entitlements
 * внешний ключ на accounts, а межбазовых ключей в SQLite не бывает.
 */
export function getBillingDb() {
  const db = getIdentityDb();
  if (!db || migrated) return db;
  db.exec(`
    CREATE TABLE IF NOT EXISTS orders (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      account_id INTEGER NOT NULL REFERENCES accounts(id),
      steam_id64 TEXT NOT NULL,
      amount_kop INTEGER NOT NULL,
      currency TEXT NOT NULL DEFAULT 'RUB',
      provider TEXT NOT NULL,
      provider_order_id TEXT,
      idempotency_key TEXT NOT NULL UNIQUE,
      status TEXT NOT NULL DEFAULT 'created',
      created_at INTEGER NOT NULL,
      paid_at INTEGER
    );

    CREATE TABLE IF NOT EXISTS entitlements (
      account_id INTEGER NOT NULL REFERENCES accounts(id),
      steam_id64 TEXT NOT NULL,
      source TEXT NOT NULL,
      order_id INTEGER REFERENCES orders(id),
      expires_at INTEGER,
      created_at INTEGER NOT NULL,
      PRIMARY KEY (account_id, steam_id64)
    );
  `);
  migrated = true;
  return db;
}
```

- [ ] **Шаг 4: Правила**

`lib/billing/store.ts`. Ключевое требование к `markPaid` — **идемпотентность в одной транзакции**: проверка статуса, перевод в `paid` и вставка права должны быть неделимы, иначе два одновременных вебхука выдадут два права. `provider` в заказе обязателен и записывается как есть: поддельные заказы никогда не должны смешаться с настоящими в отчётах.

Каждая функция при `getBillingDb() === null` возвращает безопасное значение (`null` / `false` / `"unknown"`), а не бросает — образец в `lib/identity/store.ts`.

## Готовность плана

После шести задач на сайте с `PAYWALL_MODE=stub` можно пройти весь путь: разбор → бесплатный вердикт → «Открыть полный разбор» → вход → поддельная касса → возврат → полная карточка. Повторный визит с другого устройства после входа тем же способом открывает купленное.

Чего намеренно нет: настоящей ЮКассы (появится подменой одной реализации), автоматических возвратов, отзыва права в админке, публичного шер-линка.

Перед `PAYWALL_MODE=live` владельцу нужно: договор с эквайером, чеки по 54-ФЗ, оферта с правилами возврата и сверка содержимого с банком — промпт обязывает модель материться, и это реальный повод для отказа в подключении.
