# Мост к подписке Claude для текстовой карточки

**Дата:** 2026-08-10
**Проект:** GamerType (zadrotometr.ru)
**Образец:** `ragastar/projectlevin`, каталог `tools/llm-bridge/`

## Зачем

Текстовая карточка (три архетипа, шесть характеристик, шесть подколов) сейчас
генерируется через OpenRouter на `openai/gpt-4o-mini`. Нужно перевести её на
подписку Claude Max, которая уже оплачена, вместо оплаты за токены.

Картинок это не касается — они генерируются через Wiro.ai и остаются как есть.

## Терминология

В коде текстовая карточка исторически называется «портрет» (`CardPortrait`,
`generatePortrait`). В этом документе:

- **карточка** — текстовый результат от языковой модели;
- **картинка** — арт через Wiro.ai.

Имена в коде не переименовываем: это отдельная работа, не входит в задачу.

## Решения, принятые владельцем

1. **Мост — основной поставщик, оплачиваемый ключ Anthropic — запасной.**
   Сайт не должен падать из-за моста.
2. **Ограничения доступа не трогаем.** `DISABLE_GATE=true` остаётся,
   потолок генераций не вводим. Записано в долг (см. ниже).

## Что уже есть

- Поставщик Anthropic по официальному ключу — написан, лежит в
  `lib/llm/providers/anthropic.ts`, не закоммичен. Структурированный вывод по
  схеме, кеш системного промпта, обработка отказа модели, учёт токенов.
- Явный выбор поставщика через `LLM_PROVIDER` (`resolveConfig` в
  `lib/llm/client.ts`), два значения: `openai`, `anthropic`.
- Извлечение JSON из текста (`extractJSON` в `lib/llm/client.ts`) и один
  переспрос при невалидном ответе — механика пути OpenRouter.
- 51 тест, типы чистые.

## Что есть на сервере gilgamesh

- `/usr/bin/claude` (2.1.74), плюс более свежие бинари в
  `~/.vscode-server/extensions/anthropic.claude-code-*`.
- `/root/.claude/.credentials.json` — подписка **Max**.
- Node 20 на хосте (мост запускается без контейнера).
- Сеть контейнера — `steam-psycho_default`, шлюз **172.19.0.1** (не `docker0`).

## Блокер — снят 2026-08-10

Сессия подписки была протухшей (истекла 2026-07-08), и `claude -p` висел по три
минуты молча — даже с `--debug`, при живой сети и рабочем бинаре. После
`/login` на сервере headless-режим отвечает за 1,8 секунды.

Осадок на будущее: **истёкший токен проявляется как тишина, а не как ошибка**.
Если мост однажды замолчит — проверять срок годности в
`/root/.claude/.credentials.json` первым делом. Именно поэтому проверка живости
делает настоящий запрос, а не смотрит наличие бинаря.

Отдельно: команда входа — `/login` со слэшем. Без слэша текст уходит агенту как
задача, тот идёт в API мёртвым токеном и возвращает 401 в цикле повторов.

## Архитектура

```
посетитель → /api/generate → мост (172.19.0.1:8788) → claude -p → подписка Max
                                   │
                                   └─ ошибка ─→ Anthropic по ключу ─→ OpenRouter
```

Три компонента.

### 1. Мост на хосте — `tools/llm-bridge/server.mjs`

Перенос из projectlevin. Без зависимостей, запускается под systemd.

Что переносится дословно, потому что решает реальные проблемы:

- **Промпт через stdin, не аргументом.** Текст, начинающийся с дефиса,
  `claude` иначе принимает за флаг и падает. Плюс нет предела длины аргументов.
- **`--allowedTools ''`** — мост только пишет текст, ничего не выполняет.
- **Слушает шлюз docker-сети, не `0.0.0.0`.** Снаружи не доступен.
- **Общий секрет** в заголовке `x-bridge-token`.
- **Бинарь резолвится на каждый вызов** — расширение VS Code обновляется и
  удаляет старый путь.

Три отличия от образца:

**а) Потолок одновременных вызовов.** Каждый вызов — отдельный процесс
`claude`. На gilgamesh два ядра, рядом работает NeonMailer. Держим не больше
`BRIDGE_MAX_CONCURRENT` (по умолчанию 2) одновременно; сверх того — короткая
очередь `BRIDGE_QUEUE_MAX` (по умолчанию 4). При переполнении очереди мост
отвечает **503 сразу**, а не копит ожидающих: приложению лучше мгновенно уйти
на запасной ключ, чем держать посетителя в неизвестности.

В projectlevin потолка нет — там кабинет с одним пользователем.

**б) Проверка живости говорит правду.** У образца `/health` смотрит только,
лежит ли бинарь на диске. Протухшая авторизация при этом выглядит как здоровый
сервис — на это уже напоролись 2026-08-10.

Добавляем реальную проверку: минимальный запрос к `claude -p` с коротким
таймаутом. Ответ различает три состояния: `ok` (бинарь на месте и сессия
живая), `stale` (бинарь есть, сессия не отвечает), `missing` (бинаря нет).

**Проверка выполняется только по запросу и никогда по расписанию.** Каждый
такой запрос тратит лимит подписки, поэтому: результат кешируется на
`BRIDGE_HEALTH_TTL_MS` (по умолчанию 60 с); успешная генерация обновляет кеш
бесплатно, без отдельного вызова; никаких таймеров systemd и внешних
опросов заводить нельзя.

**в) Шлюз определяется по сети приложения, а не по `docker0`.** Скрипт
установки в projectlevin берёт адрес `docker0` (172.17.0.1). У steam-psycho
своя сеть со шлюзом 172.19.0.1 — на `docker0` контейнер мост не увидит.

### 2. Поставщик — `lib/llm/providers/claude-bridge.ts`

Шлёт `{system, prompt}`, получает `{text}`.

Формат ответа схемой **не гарантирован** — это главная потеря по сравнению с
прямым API. Поэтому:

1. достаём JSON из текста (`extractJSON`, уже написан — понимает чистый JSON,
   JSON внутри ```-блока и JSON внутри произвольного текста);
2. проверяем `CardPortraitSchema`;
3. при неудаче — один переспрос с перечислением ошибок, как на пути OpenRouter;
4. второй промах — бросаем `BridgeUnavailableError`.

Тип ошибки один на все отказы моста (нет ответа, 503, таймаут, мёртвая сессия,
мусор после переспроса), чтобы вызывающий код не разбирал причины.

### 3. Переключение — `lib/llm/client.ts`

`LLM_PROVIDER` получает третье значение: `claude-bridge`.

`generatePortrait` при `claude-bridge`:

1. пробует мост;
2. на `BridgeUnavailableError` — идёт на `anthropic`, если задан
   `ANTHROPIC_API_KEY`;
3. если ключа нет — идёт на `openai` (OpenRouter);
4. если и это не настроено — бросает исходную ошибку моста.

Переход логируется одной строкой с причиной. В `GenerationResult.provider`
пишется тот, кто **реально** отработал: поле уже есть и используется в
статистике, врать ему нельзя.

Модель задаётся мостом явно через `--model`, по умолчанию `sonnet`. Образец в
projectlevin модель не пробрасывает, и всё уходит на то, что подписка отдаёт по
умолчанию, — а это Opus 4.8 с окном в миллион токенов. Для карточки избыточно, а
лимит Max он ест соответственно. Проверено на этой машине: `--model sonnet`
работает и возвращает `claude-sonnet-5`.

В `model` пишем то, что `claude` вернул в поле `modelUsage`; если пусто —
строку `subscription`.

**Цена одного вызова.** Замер 2026-08-10: на запрос «ответь словом ок» ушло
21 500 токенов ввода — это собственный контекст Claude Code, который едет с
каждым вызовом до нашего промпта. Отключение MCP и чистый рабочий каталог не
помогают (21 439 против 21 540), уменьшить нечем. Прямой API такой нагрузки не
несёт, поэтому мост тратит лимит заметно быстрее, чем можно было бы ожидать по
размеру нашего промпта.

## Настройки

Новые переменные окружения приложения:

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `LLM_PROVIDER=claude-bridge` | включает мост | — |
| `CLAUDE_BRIDGE_ENDPOINT` | адрес моста | `http://host.docker.internal:8788/generate` |
| `CLAUDE_BRIDGE_TOKEN` | общий секрет | — |
| `CLAUDE_BRIDGE_TIMEOUT_MS` | потолок ожидания | `180000` |

В `docker-compose.yml` добавляется `extra_hosts: host.docker.internal:host-gateway`.

Переменные моста (в `/etc/llm-bridge.env`, вне репозитория):
`BRIDGE_HOST`, `BRIDGE_PORT`, `BRIDGE_TOKEN`, `BRIDGE_TIMEOUT_MS`,
`BRIDGE_MAX_CONCURRENT`, `BRIDGE_QUEUE_MAX`, `BRIDGE_HEALTH_TTL_MS`.

## Установка и откат

Идемпотентный скрипт `deploy/llm-bridge-setup.sh` (перенос из образца):
генерит секрет один раз, кладёт `/etc/llm-bridge.env`, прописывает
`CLAUDE_BRIDGE_*` в `.env.local`, ставит и запускает `llm-bridge.service`,
проверяет живость.

Откат: остановить юнит, убрать строки `CLAUDE_BRIDGE_*` и `LLM_PROVIDER`,
пересобрать контейнер — вернётся прежний путь.

## Тесты

Новые (vitest, сеть не трогают):

1. **Сборка запроса.** Системный промпт и пользовательский идут в разные поля.
2. **Разбор ответа**, три случая: чистый JSON; JSON внутри ```-блока; мусор →
   `BridgeUnavailableError` после переспроса.
3. **Переход на запасной.** Мост отвечает 503 → генерация уходит на
   `anthropic`, в результате `provider` равен `anthropic`, а не `claude-bridge`.
4. **Очередь моста.** При занятых слотах и полной очереди отвечает 503, а не
   виснет.

Существующий 51 тест должен остаться зелёным.

## Риски

- **Условия использования.** Подписка Pro/Max предназначена для личной работы
  через интерфейсы Claude, а не для обслуживания посетителей сайта. Риск —
  блокировка аккаунта, вероятность растёт с объёмом. Решение владельца принято
  осознанно, зафиксировано здесь.
- **Общий лимит.** Карточки посетителей едят тот же лимит Max, что и рабочие
  сессии Claude Code на этом сервере. При наплыве владелец останется без
  инструмента.
- **Задержка.** Вызов синхронный, холодный старт `claude` плюс генерация — это
  десятки секунд. Проверить `proxy_read_timeout` у nginx.
- **Хрупкость сессии.** Мост живёт, пока жива авторизация в `/root/.claude`.
  Протухла — молчаливая деградация на запасной ключ. Поэтому переход **обязан**
  попадать в лог.

## Долг (в эту работу не входит)

1. **Ограничения доступа.** `DISABLE_GATE=true` — любой посетитель запускает и
   карточку, и картинку. Решение владельца: не трогать.
2. **Адрес сайта в превью для соцсетей.** В Dockerfile домен уже
   `zadrotometr.ru`, но в `.env.local` на сервере осталась строка
   `NEXT_PUBLIC_BASE_URL=https://gamertype.fun`, которая перебивает сборку в
   серверном рендеринге. Кнопки «поделиться» работают верно (значение зашито в
   клиентский бандл), а мета-теги для соцсетей ведут на мёртвый домен.
   Чинится удалением одной строки.
3. **Ветка `fix/pre-launch-audit` не смержена в master**, хотя запушена.
4. **Публичная ссылка на результат.** После перевода доступа на серверную
   проверку чужая ссылка показывает витрину вместо карточки — вирусность
   сломана.
5. **Имена в коде.** `portrait` означает текст, что путает при разговоре о
   картинках.
